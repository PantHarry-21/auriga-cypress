
Method – Method Upload List View – Test Scenarios

Verify that an authorized user can navigate to the Method Upload list view from the Method menu.  
Verify that the grid loads with default columns – S.No, Method ID, Product Name, Upload File, Active, Created By, Created Date, Updated By, Update Date, Location, Edit. 
Verify that the New Method Upload button is visible and enabled for users with create permission and hidden/disabled for others.  
Verify that the search box returns records when searching by Method ID. 
Verify that the search box returns records when searching by Product Name. 
Verify that searching with text that does not exist shows an empty state message and no records. 
Verify that pagination controls (page numbers, Next, Previous) work correctly and the “Showing X results” text updates accordingly. 
Verify that the “Show per page” dropdown (10/20/50 etc.) changes the number of records displayed. 
Verify that clicking the Columns button opens the manage-column panel and allows toggling column visibility.  
Verify that hiding a column in Columns immediately removes it from the grid and showing it again restores it.  
Verify that S.No / Method ID columns are sortable (if supported) and sorting ascending/descending reorders rows correctly. 
Verify that the Upload File column shows a PDF icon for rows where a file exists and handles rows with no file gracefully (icon hidden or disabled).  
Verify that clicking the PDF icon opens/downloads the uploaded file; verify behavior for multiple different records. 
Verify that the Active column correctly shows status (e.g., “Active” pill) matching the record’s actual status.  
Verify that filter section fields (S.No, Method ID, Product Name, Created By, Created Date, Upload File, Active) appear and are usable. 
Verify that filtering by S.No returns only that serial number row. 
Verify that filtering by Method ID returns only records with the selected Method ID. 
Verify that filtering by Product Name returns only records for that product. 
Verify that filtering by Created By returns only methods created by the chosen user. 
Verify that filtering by Created Date using the date picker returns records created on the selected date and none for other dates. 
Verify that filtering by Upload File (All / With File / Without File – if options exist) works correctly. 
Verify that filtering by Active status (Active / Inactive) returns only records in that status. 
Verify that applying multiple filters together (e.g., Product Name + Active + Created By) returns the intersected result set. 
Verify that Clear All Filters resets all filters and reloads the full dataset.  
Verify that list view performance remains acceptable with many records (e.g., no noticeable lag when scrolling horizontally or changing pages). 
Verify that selection checkboxes allow selecting single/multiple rows and that “0 row(s) selected / X row(s) selected” text updates correctly. 
Verify that no unintended bulk operations occur when rows are selected (if bulk actions aren’t implemented yet). 
Verify that clicking the Edit icon on a row opens the corresponding Method Upload record in edit mode.  
Verify that users without edit permission do not see the Edit icon or receive an authorization error when trying to access edit URL. 
Verify that reloading the page behaves as expected — either retaining filters/search or resetting to defaults as per design. 


 Method – New Method Upload (Add / Edit) – Test Scenarios

Verify that clicking New Method Upload opens the Method Upload form in a modal with all fields visible: Method ID*, Product Name, Version No, Message, Expiry Date*, Upload Method File*, Active.  
Verify that Method ID is a searchable dropdown listing all available method records and that selecting a method auto-populates any linked data (if expected).  
Verify that the user cannot save the form when Method ID is left blank and an appropriate validation message is shown.  
Verify that Product Name accepts alphanumeric characters and special characters within allowed length and is optional/mandatory as per business rule.  
Verify that Version No accepts valid version formats (e.g., 1, 1.0, 01, v1.0) and handles over-length or invalid characters with a validation message.  
Verify that Message field accepts free text up to the specified character limit and shows an error when the limit is exceeded.  
Verify that Expiry Date uses a date picker and the user can select a valid future date.  
Verify that the system prevents selection of an invalid Expiry Date where business rules apply (e.g., past date not allowed) and shows a clear error. 
Verify that Upload Method File allows selecting a file from the local machine and displays the selected filename.  
Verify that only allowed file types (e.g., PDF / DOCX as per requirement) can be uploaded, and that uploading a disallowed type (e.g., .exe, .jpg) shows a validation error. 
Verify behavior when uploading a very large file that exceeds configured size limits (proper error and no save). 
Verify that all mandatory fields (Method ID, Expiry Date, Upload Method File, and any others marked with *) are enforced on Save.  
Verify that clicking Save with all required fields valid creates a new Method Upload record and closes the modal with a success message.  
Verify that the newly created record appears in the Method Upload list view with correct Method ID, Product Name, Active status, Created By, Created Date and that the PDF icon is present. 
Verify that clicking Cancel or the close icon (X) closes the modal and discards unsaved changes.  
Verify that field-level validation messages disappear once the user corrects the input and tries again. 
Verify that whitespace at the beginning or end of Method ID and Product Name is trimmed before saving (no duplicate caused purely by spaces). 
Verify that attempting to create a duplicate upload (same Method ID & Version No combination, if uniqueness is required) is blocked with a useful error message. 
Verify that the Active checkbox is checked by default for a new upload and can be unchecked to create an inactive record.  
Verify that editing an existing record loads all saved values correctly in the form, including Active state and file name (or indication that a file already exists). 
Verify that changing the file in edit mode replaces the existing upload and the latest file is opened from the grid icon. 
Verify that editing and saving with invalid changes (e.g., clearing a required field) is not allowed and shows appropriate errors. 
Verify that simultaneous saves for the same Method ID/version (from two users) are handled gracefully without data corruption (latest save or controlled conflict). 
Verify that the form remains responsive and scrollable on different screen resolutions, and all fields are reachable via scrolling. 
Verify keyboard navigation (Tab order) cycles through fields in logical sequence and focuses on the first invalid field when Save fails. 
Verify that unauthorized users cannot open the New Method Upload form or cannot save changes (depending on permission design). 
Verify that session timeout while the form is open leads to a graceful error when saving (e.g., redirect to login, no partial save). 
Verify that if file upload fails due to network/server error, the user sees a clear error message and the record is not created. 
Verify that partial entry followed by Cancel does not create any record and does not leave orphaned file uploads on the server (if trackable). 
Verify that audit fields (Created By/Date, Updated By/Date) are populated/updated correctly on create and subsequent edits of a Method Upload record.
